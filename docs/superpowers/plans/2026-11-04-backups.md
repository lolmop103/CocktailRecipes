# Off-site encrypted backups Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A nightly `age`-encrypted archive of CocktailRecipes' SQLite database and BinMark's Postgres dump and photos, stored in a Cloudflare R2 bucket with locks and expiry, with alerts and one proven restore.

**Architecture:** This repo gets a `db.backup()` snapshot command in its image. BinMark's `infra/backup/` gets the host scripts: `backup.sh` (cron), `restore.sh`, `pull-local.sh` (owner's machine) and `verify-bucket.sh`. `rclone` talks to R2, `age` encrypts, healthchecks.io pings report success or failure. The scripts are tested in an Alpine container with a fake `docker`, a local-filesystem `rclone` remote and a real `age`.

**Tech Stack:** TypeScript + better-sqlite3 + Vitest (this repo); Bash, `age`, `rclone`, `shellcheck`, Docker (BinMark).

**Spec:** `docs/superpowers/specs/2026-11-04-backups-design.md`

## Global Constraints

- Retention: `daily/` expires after 8 days, `weekly/` after 29, `monthly/` after 395; bucket locks 7, 28 and 30 days. Archive ceiling 400 MB (`419430400` bytes): over it the upload stands but the run pings `/fail`.
- Cron 03:00 UTC, `nice -n 19` and idle IO priority, one run at a time (`flock`); staging directory mode 700, removed by a trap on every exit.
- Healthchecks: `backup` expects a ping daily (alert after 26 h); `local-copy` expects one monthly (alert after 35 days).
- The VPS holds only the `age` public recipient, one bucket-scoped R2 token and the healthchecks URL, in a `chmod 600` file. The private key, the owner's R2 token and bucket rule edits never go on the VPS.
- The snapshot never imports `connection.ts` (no migration, no database creation) and is not imported by `index.ts`.
- No data (dumps, photos, archives, keys, tokens) is ever committed.
- Conventional Commits; commits and PRs carry the human author only, no tool attribution; never bypass hooks.
- Branches are cut from `develop` and PR'd into `develop`; a human merges. In BinMark use `git worktree add` from `develop` (its working copy may sit on another branch).
- This repository is public: no secrets, hostnames of the production server, or account identifiers in files or PR text.

## Review Focus

- A first-ever run with an empty photos directory still produces a restorable archive.
- Photo file names with spaces and non-ASCII characters survive the round trip.
- A missing `age`, `rclone` or `docker` makes the run fail loudly with a `/fail` ping, never exit 0.
- A re-run after a half-finished night (daily uploaded, weekly or monthly copy failed) completes the missing copies instead of exiting early.
- The staging directory is gone, and no secret appears in stdout or stderr, after both success and failure.

## Spec refinement to confirm at plan review

The spec says the monthly copy is made "on the 1st". This plan makes it the first successful run of each UTC month, so a failed 1st is repaired by the next night's run instead of losing the month. Nothing else differs from the spec.

# Branch 1: `feat/db-snapshot` (CocktailRecipes)

### Task 1: Snapshot core and command

**Files:**

- Create: `server/src/lib/snapshot.ts`, `server/src/scripts/snapshot.ts`, `server/tests/snapshot.test.ts`
- Modify: `server/package.json` (script `"snapshot": "tsx src/scripts/snapshot.ts"`)

**Interfaces:**

- Produces: `snapshotDatabase(dataDir: string, verify?: (file: string) => void): Promise<string>` resolves to `<dataDir>/snapshots/cocktail.db`. `verifyIntegrity(file: string): void` throws `Error('integrity check failed: <result>')` unless `PRAGMA integrity_check` returns exactly `ok`. A missing source throws `Error('database not found: <path>')` and creates nothing. Command: `node server/dist/scripts/snapshot.js`, reads `DATA_DIR` (required; missing → `snapshot: DATA_DIR is not set`, exit 1), prints the path on stdout, any error prints `snapshot: <message>` on stderr and exits 1.

- [ ] **Step 1: Write the failing tests** in `server/tests/snapshot.test.ts` (temp directory per test, real file databases):
  - `copies every row of a populated database`: 100 rows in, the snapshot holds the same 100 rows.
  - `succeeds while another connection is writing`: a writer connection inserts in a loop during the snapshot; the result passes `verifyIntegrity` and holds at least the initial rows.
  - `rejects and creates nothing when cocktail.db is missing`: message `database not found`, no `cocktail.db`, no `snapshots` directory.
  - `replaces an earlier snapshot`: two calls, one file, second call's content.
  - `writes only to <dataDir>/snapshots/cocktail.db`: the returned path equals that string exactly.
  - `removes the copy and rejects when verification throws`: pass a throwing `verify`; the file is gone and the promise rejects with its message.
  - `verifyIntegrity throws on a corrupted file`: overwrite bytes inside a later page of a populated copy.
  - `completes a 5 MB database in under 2000 ms`.
- [ ] **Step 2: Run to see them fail:** `pnpm --filter cocktail-server test -- snapshot` → fails, module not found.
- [ ] **Step 3: Implement** `snapshot.ts` with better-sqlite3: open source with `{ readonly: true, fileMustExist: true }`, `db.backup()` into the destination, close, call `verify`; on any failure delete the destination. Then the command file as the thin wrapper described above.
- [ ] **Step 4: Run to see them pass:** `pnpm --filter cocktail-server test -- snapshot` → all pass.
- [ ] **Step 5: Commit** `feat(server): add a consistent database snapshot command` (files above).

# Branch 2: `feat/backup-scripts` (BinMark, from `develop`)

### Task 3: Test harness and `backup.sh`

**Files:**

- Create: `infra/backup/lib.sh`, `infra/backup/backup.sh`, `infra/backup/tests/run.sh`, `infra/backup/tests/in-docker.sh`, `infra/backup/tests/shims/{docker,curl,df}`, `infra/backup/tests/backup_test.sh`

**Interfaces:**

- Produces (`lib.sh`): `log <msg>`, `require_tools <name...>` (exits 1 naming the missing tool), `ping_ok`, `ping_fail <step> <detail>`, `utc_date` (honours `BACKUP_DATE` for tests, default `date -u +%F`).
- Produces (`backup.sh`): configuration only from the environment file named by `BACKUP_ENV` (default `/etc/backup/backup.env`): `AGE_RECIPIENT`, `BACKUP_REMOTE` (e.g. `r2:bucket-name`, rclone config via `RCLONE_CONFIG_R2_*` variables), `HC_BACKUP_URL`, `BINMARK_COMPOSE` (compose file), `COCKTAIL_COMPOSE`, `STAGING_ROOT`, `BACKUP_MAX_BYTES` (default 419430400), `BACKUP_DATE` (tests). Archive layout: `cocktail.db`, `binmark.dump`, `photos.tar`. Objects: `daily/<date>.tar.age`, `weekly/<date>.tar.age`, `monthly/<YYYY-MM>.tar.age`.
- Produces (tests): `run.sh` provides `assert_eq`, `assert_file`, `assert_no_file`, `assert_contains`, `new_sandbox` (temp bucket directory, `PATH` with shims first, fresh `age` test key pair, `rclone` remote of type `local`); `in-docker.sh` runs `run.sh` in `alpine` with `bash age rclone shellcheck tar gzip coreutils` installed.
- Shims: `docker` answers the `compose … exec/cp/ps` calls `backup.sh` makes with canned files and records calls, with switches to fail one step; `curl` records ping URLs; `df` reports a configurable free size.

- [ ] **Step 1: Write the failing tests** in `backup_test.sh`, one function per case, each asserting the exact result:
  - `happy_path`: exit 0; `daily/<date>.tar.age` exists; decrypting with the test identity gives a tar with `cocktail.db`, `binmark.dump`, `photos.tar`; exactly one success ping, no fail ping; staging directory removed.
  - `sunday_makes_weekly`: `BACKUP_DATE` a Sunday → `weekly/<date>.tar.age` identical to the daily; a weekday → no weekly.
  - `first_run_of_month_makes_monthly`: `monthly/YYYY-MM.tar.age` created once; the next day makes none.
  - `rerun_same_day_does_not_upload_again`: second run leaves the daily's modification time unchanged, exits 0, pings success.
  - `rerun_completes_missing_copies`: delete the weekly after a Sunday run, run again → weekly exists, daily untouched.
  - `snapshot_failure`, `pg_dump_failure`, `photo_tar_failure`: exit non-zero, one `/fail` ping naming the step (`snapshot`, `pg_dump`, `photos`), nothing uploaded, staging removed.
  - `upload_failure_retries_once`: unwritable remote → two upload attempts, then `/fail` naming `upload`.
  - `over_ceiling_still_uploads_and_alerts`: `BACKUP_MAX_BYTES=1` → object exists, `/fail` ping mentions the size.
  - `low_disk_stops_before_dumping`: `df` shim reports little space → `/fail` with free and needed sizes, nothing dumped.
  - `concurrent_run_is_refused`: a second run while the lock is held exits non-zero, sends no ping.
  - `missing_tool_fails_loudly`: `age` removed from `PATH` → exit non-zero, `/fail` naming `age`.
  - `unicode_and_spaced_photo_names_round_trip` and `empty_photos_dir_is_restorable`.
  - `no_secret_in_output`: the R2 secret and healthchecks URL never appear in stdout or stderr.
  - `shellcheck_is_clean` for every `*.sh`.
- [ ] **Step 2: Run to see them fail:** `bash infra/backup/tests/in-docker.sh` → fails, `backup.sh` missing.
- [ ] **Step 3: Implement** `lib.sh` and `backup.sh` as the nightly flow in the spec (flock, `nice`/`ionice`, trap, disk check = 2 × photos size, `age -r`, upload with one retry, tier copies by `rclone copyto` between bucket paths, existence checks make re-runs idempotent, `/fail` on the first failed step). Never `set -x`; never echo environment values.
- [ ] **Step 4: Run to see them pass:** `bash infra/backup/tests/in-docker.sh` → all pass, shellcheck clean.
